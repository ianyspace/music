# Music Space

一个独立的静态音乐播放器：Next.js 15（Pages Router）+ Sass，构建为纯静态站点发布到
GitHub Pages —— https://ianyspace.github.io/music/

代码从博客仓库 `space` 的音乐模块整体切出（`components/Music/` + `pages/music/`），
播放逻辑未改动，只把博客专有的部分替换掉了（详见 `AGENTS.md` 的「迁移时替换了什么」）。

`/h5` 与 `/desktop` 是**两棵互不引用的组件树**：`components/Music/h5/` 与
`components/Music/desktop/` 各自拥有外壳与全部样式，共用 `components/Music/core/`
（播放状态机、`<audio>`、页面 head、两个面板的内容）。目录与约定见 `AGENTS.md`。

## 特性

- **两种布局，两棵完全独立的组件树**：窄屏 `/h5`（列表 + 迷你条 + 全屏播放页），
  宽屏 `/desktop`（沉浸式：唱片 / 歌词占满全屏，列表、胶囊播放条、设置都浮在它上面）。
  `/` 按 900px 断点自动跳转。
  两套布局互相**不引用任何一个文件**，只共用 `components/Music/core/` 里的播放状态与面板内容 ——
  改一边不会碰到另一边。
- **桌面端是沉浸式界面**：唱片（或歌词）占满整个视口，列表、胶囊播放条、设置按钮都是浮在
  它之上的独立浮层 —— 折叠列表、开关弹窗都不会让唱片挪一个像素。表面是纯 CSS 的
  `backdrop-filter`（没有 WebGL、没有玻璃库），**只有深色一套**（手机端仍然是浅色 / 深色
  可切，两边互不影响），浏览器不支持时自动回退成半透明底色。
- **两套曲库**：默认走公共 Cloudflare R2 桶（**完全不需要授权**）；连接自己的 Google 云盘后
  切换成自己的文件夹，断开则回落到公共曲库。
- **音频缓存**：音频下载成 blob 存进 IndexedDB，**30 天过期，每播一次就自动续期**，
  30 天没播放过才会清除。缓存管理面板能看到每首的过期时间、占用空间，逐条删除，
  也可以一键「全部缓存」（并发 3）或「全部删除」。
- **歌词**：读取同名 `.lrc` / `.txt`，支持逐行滚动与纯文本模式。
- **封面**：读取同名图片（R2 是 `jpg` / `jpeg` / `png` / `webp`，云盘是任何图片），
  列表、迷你条、播放页唱片、缓存管理、**以及锁屏 / 耳机键上的系统封面**里都显示；
  **没有封面（或图加载失败）就退回原来的渐变色封面**，不需要额外准备什么。
- **播放器细节**：单例 `<audio>`（切页面不中断）、顺序 / 列表循环 / 单曲循环 / 随机
  （**默认随机**，且选择会记住）、随机播放会提前抽签好下一首以便预取
  （iOS 后台续播）、Media Session 锁屏控制、无音量控件（交给系统）。
- **列表可以自己管**：把某首置顶（再点一次「取消置顶」就回到原来的位置）。
- **喜欢**：公共曲库的歌可以加入「我喜欢」，列表顶栏一键只看喜欢的歌。
  确认过 QQ 号的话，喜欢**按号码存在 Cloudflare D1 里**，换设备也能看到；
  **没确认也能喜欢**，那种喜欢只留在这台设备的浏览器里（确认号码时会一起带过去）。
- **听歌排行**：确认 QQ 号之后，每首歌的播放次数和最后一次播放时间会记进 Cloudflare
  的 D1 数据库，在「账号」面板点「听歌排行」升起一块面板看 —— 全部和最近 7 天各一份，
  关掉它就回到歌曲列表。
  **一首歌要真的听了 10 秒以上才算一次播放** —— 点一下播放、两秒后切走不算，
  把进度条拖到底也不算，因为那些都不是在听。
  **上报不挡听歌**：播放事件先写在本机日志里再发请求，发不出去就留在本地，「账号」面板有
  「同步」按钮可以手动补传（播放记录和喜欢共用这一个按钮），确认送达的记录才会从本地删掉。

> **断网打不开网站**：没有 Service Worker，页面外壳由 GitHub Pages 直接提供。
> 已经打开着的页面断网后还能继续播放**已缓存**的歌，但重新打开需要网络。
> 详见下面的「离线与缓存」。

## 快速开始

```bash
npm install
npm run dev          # http://localhost:3000
npm run build        # 静态产物在 out/
```

## 曲库从哪来

默认直接连已部署的 Worker（`config/index.js` 的 `music.workerUrl`）：

```
GET https://space-music.ianyscript.workers.dev/tracks
```

换成自己的 R2 桶 / Worker 就改这个值，或用环境变量 `NEXT_PUBLIC_MUSIC_WORKER_URL` 覆盖。
Worker 源码在 `cloudflare-worker/`，部署方式见 `cloudflare-worker/README.md` —— 同一个
Worker 还提供 `POST /plays` / `GET /stats`（播放次数）和 `GET /likes` / `POST /likes`
（我喜欢），两者都存 D1，地址也走这个配置。

> 上传新歌后想立即看到，请求带 `?refresh=1`，或等清单缓存（300 秒）过期。
> 歌曲的同名封面 / 歌词是 **Worker 列举桶时配对**的，所以给公共曲库加封面或歌词，
> 需要**重新部署 Worker** 才生效；页面这边对旧版 Worker 也能工作（自己按 `.jpg` 猜一次）。

## 连接自己的 Google 云盘

手机端：列表右上角的 ⋮ → 「音乐库」→ 「连接 Google 云盘」（列表还是空的时候，
中间那个「连接 Google 云盘」按钮会直接开这一步）。
桌面端：列表的 ⋮ → 「谷歌云盘链接」，或右上角齿轮进设置。填入自己的 OAuth Client ID
（`drive.readonly`，只需一次，存在 localStorage）。公共曲库不需要任何授权，所以不填也能正常播放。

## 离线与缓存

断网不能打开网站了：**没有 Service Worker**。它以前负责预缓存页面外壳，但代价太大 ——
部署后旧外壳会继续吐旧 JS，而且「我现在看到的是不是最新版？」没法靠刷新回答。现在
页面外壳直接由 GitHub Pages 提供，一次普通请求就够快，不需要中间层。

留在浏览器里的只有**数据**，但两者寿命不同：

- **音频 blob** 存 IndexedDB（`lib/cache/indexedDb.js` + `components/Music/audioCache.js`）。
  **30 天过期，每播一次就续期到 30 天后**，30 天没播放过才清除；缓存管理面板会把每首的
  过期时间显示出来。所以「缓存过的歌」需要偶尔听一下才会一直在。
- **曲库清单** 存 localStorage（`components/Music/librarySource.js`），永久不过期 ——
  清单只是一个 URL 数组，让它过期只会让人看到空列表，没有任何收益。
- 早期版本写入的带 TTL 的旧记录仍然按原过期时间处理，不会被意外「永久化」。

选 IndexedDB / localStorage 而不是 Cache API，是因为这里能被「缓存管理」面板统计、
逐条删除、一键清空 —— 你始终知道占了多少空间、能自己清掉。

> 已经访问过旧版本的浏览器里还装着那个 Service Worker，而且删掉 `sw.js` 并不会让它消失。
> `utils/retireServiceWorker.js` 会在加载时把它注销掉并清掉它留下的缓存。等旧外壳自然
> 淘汰完，这个文件就可以删了。它只做注销，永远不会再注册任何东西。

## 部署

推 `master` 会自动触发 `.github/workflows/deploy.yml`。

**Pages 的 Source 必须选 `GitHub Actions`**：仓库 Settings → Pages → Build and deployment →
Source 选 `GitHub Actions`，别留在「Deploy from a branch」。

留在分支模式的话，GitHub 会额外跑一次自己的 Jekyll 构建，并且发布的是**仓库根目录**而不是
`out/`，两个部署互相竞争，线上会**时好时坏**：一会儿正常，一会儿首页变成 Jekyll 渲染的
README、而 `/h5/`、`/desktop/` 全部 404。别因为刚推完看着正常就以为没事。

一次性确认方法：访问 `https://ianyspace.github.io/music/README.md`，如果能打开（200），
说明发布的是仓库根、也就是这个设置还没改对。

工作流在发布前会校验 `out/` 里的关键文件（三个页面、`.nojekyll`、`_next/static`），
缺任何一个都会直接让 CI 失败；同时会确认 `out/sw.js` **不存在** —— 因为它已经被有意移除，
再出现就说明又在发布旧外壳了。

## 快捷键 / 交互

两套布局共用同一份状态，控件的位置不同、行为一致。

| 布局 | 位置 | 操作 |
| --- | --- | --- |
| 都有 | 列表右上角 🔍 | 展开搜索框，过滤当前曲库 |
| 手机端 | 列表**左上角应用图标**（带状态点） | 升起**「账号」**面板：确认 / 清除 QQ 号、进「听歌排行」、手动同步本机记录。**右下角那个点就是 QQ 状态**：灰=未确认，绿=已确认 |
| 手机端 | 列表右上角 ⋮ | 底部抽屉三项：**音乐库**（当前曲库 / 文件夹 / 连接自己的云盘 / 刷新）、**缓存管理**、**切换外观**。面板都是抽屉页：顶部只有一个「收起」 |
| 手机端 | 「账号」面板 → 听歌排行 | 升起一块面板：全部 / 最近 7 天两份播放次数排行，右上角 ⟳ 重新拉取；关掉它回到歌曲列表 |
| 都有 | 每行右侧 ⋮ | 行抽屉（封面 + 歌名 + 作者）：**置顶 / 取消置顶** |
| 手机端 | 行抽屉（公共曲库的歌） | 多一项 **喜欢 / 取消喜欢**，加入「我喜欢」；Drive 曲库的歌不显示这一项 |
| 手机端 | 列表右上角 ❤ | **只看喜欢**：列表只留下喜欢的歌，再点一下恢复 |
| 都有 | 右下角浮现的 ↓ | 播放中的那行滚出屏幕时出现（箭头指向一个点：跳到正在播的那一行），点一下平滑滚回去并闪一下。手机端浮在迷你条右上方，桌面端在列表右下角 |
| 都有 | 播放页 / 歌词 | 点唱片切歌词，点歌词切回唱片 |
| 都有 | 缓存管理 | 顶部 ⟳ 重新统计；每行显示过期时间与大小、× 单独删除；底部「全部缓存」（并发 3）与「全部删除」 |
| 手机端 | 播放详情页 ⋮ | 播放设置抽屉：唱片波纹 |
| 手机端 | 底部迷你条 | 点一下打开全屏播放页；只有播放 / 下一首在原位生效 |
| 桌面端 | 左上角 ▤ | 折叠 / 展开歌曲列表（折叠状态会记住）。**有歌在放、鼠标又不在列表上时，3 秒后列表会自己收起**；暂停或列表空了会自动展开 |
| 桌面端 | 右上角齿轮 | 设置弹窗：当前曲库、音乐库（文件夹 / 断开连接）、连接自己的云盘、外观（主题 / 左侧列表 / 唱片波纹）、缓存 |

「置顶」是把歌放进一份**排名**里，不是把整个列表重排一遍；「取消置顶」就是从这份排名里
把歌拿掉，它会落回曲库本来的顺序 —— 所以取消之后的位置就是没置顶过的位置，不需要记着它原来在哪。

「喜欢」只针对公共曲库（云盘的文件 id 出了那个账号就没有意义），但**不需要 QQ 号**：
没确认号码时喜欢只存在这台设备的浏览器里，确认之后这份喜欢会跟着号码上传，换设备也能看到。
播放页旋转唱片模式下，歌名那一行最右侧也有一颗心，可以直接喜欢 / 取消。

「账号」面板里确认的 QQ 号做三件事：给你一张 QQ 头像（画在面板的身份卡上）、
作为听歌排行的归属、以及作为「我喜欢」的归属。号码存在本机浏览器（`music:setting:qq`），
头像取自 QQ 的公开头像接口；**它不校验号码是否真的存在** —— 那个接口对不存在的号
也给一张占位图，所以这是「你自己认得的头像」，不是身份验证。取不到图（网络不通、
接口被挡）时退回默认的音符头像，面板会直说。
确认之前那块地方是输入框，确认之后**只剩那张卡**，卡自己带一个「清除」按钮 ——
清除之后又变回输入框，所以「我的号存上了没有」永远只有一个答案在屏上。

播放次数和「我喜欢」是唯一会离开这台设备的数据：它们写进 Cloudflare D1
（Worker 的 `POST /plays` / `POST /likes`），读取也是（`GET /stats?qq=…` / `GET /likes?qq=…`）。
因为 QQ 号不是凭据，这份数据**没有鉴权** —— 知道一个号码就能看到它的排行和喜欢，
和知道号码就能取到它的头像一样。介意的话就别绑。
